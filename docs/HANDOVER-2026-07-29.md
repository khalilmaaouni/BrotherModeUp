## 2. The one command that gates everything

```bash
python3 tools/test_all.py
```

Expected right now: `445 tests across 4 suites, 2 skipped, ALL GREEN`, exit 0.
Takes about 47 seconds.

Run it after your last edit, before any claim of done. Quote its output. There
are FOUR suites, not one, and the runner exists because "run the tests" used to

It runs them SERIALLY on purpose. The suites rename a module aside mid-run, so

into a parallel runner; you will manufacture flakes and then debug the wrong

`SUITES` list. If you add a suite, add it there.

## 3. Environment constraints that will bite you

| Constraint | Consequence |
|---|---|
| **Python 3.9 is the floor** | CI pins 3.9 for the store suite. No `X \| Y` unions, no `match`, no builtin-generic annotations evaluated at runtime. |
| **Standard library only** | No dependencies may become mandatory. No Docker, Postgres, Node, Chroma, API keys. |
| **No network, no subprocess** in shipping `tools/*.py` | Mechanically enforced by `test_bm.py`. One documented exemption: `bm_autosave.py` (drives git). Test files are exempt by prefix, which is why the runner is named `test_all.py`. |
| **Every write site is inventoried** | `tools/write_sites.json` + a test. Add a file that writes anything, including stdout, and the suite refuses until you review and list it. |
| **Every `conn.execute` must route through `_exec`** | Or be listed in the `exempt` dict in `test_bm_store.py` with a stated reason. DDL and transaction control are the accepted exemptions. |
| **No em or en dashes** anywhere | Founder rule. Code, comments, output, docs, commit messages. |
| **CI matrix** | ubuntu + macos for the main suite; ubuntu + macos + windows and Python 3.9 + 3.x for the store suite. Windows is asserted by CI only; nobody here has a Windows machine. |

## 6. THE MISTAKES LEDGER

This is the most valuable section. Three consecutive sessions produced the same
pattern, and it is the single most expensive habit in this project.

### The meta-lesson: a green suite is not evidence

**Every serious defect below was found by driving the real CLI against a real
store, while the full suite was green.** Not one was caught by writing more
tests first.

Working rule for you: build fixtures from a REAL store (create one, then revert
it), and probe the actual binary, not only the API.

### Defects found and fixed, with the mechanism

| # | Defect | How it hid | Mechanism |
|---|---|---|---|
| 1 | `executescript()` COMMITS IMPLICITLY, silently ending the migration's `BEGIN EXCLUSIVE`. The DDL landed piecemeal; the migration LOOKED successful while its all-or-nothing guarantee was false. | No test opened a real schema-1 store. | DDL split into individual statements; `_split_ddl` carries the incident; a test asserts statement counts. |
| 2 | `ReadOnlyStore` borrows `Store._verify_schema_or_raise` unbound and lacked `_refuse_without_quarantine`, so `verify` on an old store raised `AttributeError` instead of refusing. | No test opened an out-of-date store through the READ-ONLY path. | Method borrowed explicitly + regression test. |
| 3 | An exception during migration leaked the database handle. Invisible on POSIX, fatal on Windows. | POSIX lets you delete an open file. | Close before re-raise; caught by the suite's own leak detector. |
| 4 | **All sixteen** new refusals were written `OwnershipRefused(message, reason=...)` against a signature of `(reason, message)`. Every one raised `TypeError` instead of the intended refusal. | **A test asserting "something raised" passes either way.** The guard stopped the write by accident, with the wrong type and a useless message. | Structural AST test asserting every call passes a literal kebab reason code first. |
| 5 | Retrieval answered "what colour should the orb be" with a rule about pushing to GitHub. Scope eligible, relevance zero, returned anyway. | Nothing tested for the ABSENCE of an irrelevant result. | Relevance floor; `severity='gate'` exempt so safety rules still appear. |
| 6 | `require_root()` returns `(root, source)`, not a path. Crashed on the CLI's first invocation. | New file, no prior caller. | Unpacked in one named place. |

### Self-inflicted, worth recording

- **A regex repair damaged two PRE-EXISTING call sites**, inserting a second
  reason code into refusals that were already correct. The suite caught it.
  Lesson: after any bulk regex over a large file, diff against HEAD and confirm
  the only changes are the ones you intended. The final diff carried exactly one
  deletion, which was the line deliberately restructured.
- **A stale status file cost a whole planned loop.** `NOT-FINALIZED.md` item 5
  said the adopt defect was OPEN and had "survived two audits". It had already
  been fixed, tested, and calibrated. Reproducing it before fixing it is the only
  reason a second fix was not layered on a working one. **Reproduce before you
  fix, even when your own notes say the bug is live.**
- **An empty scan result from a FAILED command is not a pass.** A secret scan ran
  after a failed `git fetch` and printed nothing. Also `exit=$?` after a pipe
  reads the LAST command's status, not the one you care about.

### Test-calibration discipline used here

For any load-bearing guard: prove the test passes with the fix, REINJECT the
defect, prove it fails for the intended reason, restore, prove it passes again.
Done for the migration atomicity guard and for the `test_all.py` gate in both
directions. A test written backwards from the fix confirms your own assumption.

## 7. OPEN BUG LIST

Full register is `docs/NOT-FINALIZED.md`, 17 numbered items. Status words mean
exactly one thing: OPEN (reproduced, not fixed), PARTIAL (something landed, not
what was asked), UNPROVEN (believed correct, never demonstrated), DEFERRED
(deliberately not done, with a reason).

### Highest harm

1. **Item 1, UNPROVEN, highest harm.** Never run on a real day of the founder's
   work. Every score inherits that caveat. Only using it closes this.
2. **Item 15, OPEN (partly closed).** `dump` redaction is a secret SCRUBBER, not
   a redactor: it removes secret-shaped substrings and lets ordinary prose and
   absolute paths through. CLOSED for the learning tables, where `raw_text`,
   evidence `excerpt` and `task_excerpt` are now WITHHELD entirely. Still OPEN
   for `records.evidence`, `records.objective`, `digests.body`,
   `transitions.note`.
3. **Item 2, OPEN.** Bash writes bypass the fence hook. The `PreToolUse` hook
   sees Edit/Write/NotebookEdit only. So "one writer per file" holds for tools
   the hook sees, not for the shell. Needs a design, not a patch.
4. **Item 17, OPEN.** The correction filter is English-only with a 400-character
   cap. Measured: 2 of 5 real messages captured; a French correction and a long
   one were dropped SILENTLY. The founder works in French. Loop 4 closes this.

### Also open

- **Item 3, PARTIAL.** Session identity is harder to forge, not unforgeable. Any
  process running as the user can read the token file.
- **Item 4, PARTIAL.** Handovers are lock-serialized, not transactional. The
  follow-up shape (a handovers table) is recorded in the code.
- **Item 6, OPEN.** Recovered work is owner-only on POSIX only. Windows ACLs are
  not set.
- **Item 7, PARTIAL.** Lazy core missed its own target: 1,490 tokens against a
  goal of 400 (down from 10,407). Target stands, unmet, not re-baselined.
- **Item 8, UNPROVEN.** Nothing demonstrates a session actually LOADS the right
  reference file when it should. The planned Stop-hook guard is not built. This
  is silent-degradation risk on exactly the dimensions the project wins.
- **Item 9, OPEN.** Three scoring checks red. Worse: the gate FAILS locally and
  PASSES in CI, because CI has no vault and returns NO-DATA. A gate that cannot
  fail where it runs is not gating.
- **Item 10, OPEN, mitigated.** Suites cannot run concurrently. `test_all.py`
  makes the safe path the easy path; the module-rename design is unchanged.
- **Item 11, DEFERRED.** Public install (one-command installer, Windows hook
  dispatcher) not started.
- **Item 12, DEFERRED.** The independent second-model re-audit never ran. "All 17
  findings closed" rests on the author's own verification plus CI, not on an
  outside adversary.
- **Item 13.** Orchestration practice did not improve, only the outcome did.
  Fences were written AFTER dispatch three times.
- **Item 14.** Findings 16 to 63 of the FIRST audit were triaged by class, never
  individually re-proven.
- **Item 16, OPEN.** `bm_store.py claim --help` claims a record literally named
  `--help`. Cosmetic in isolation. `bm_learn.py` deliberately does NOT inherit
  this: unknown flags exit non-zero and name themselves.
