Risk management, insights and alerts

Alert 1. The released sibling build is missing its own headline command

What it is
An internal card tells a data engineer that the whole workflow is two commands and that the first is sbe review-route. On the version installed on this machine, that command does not exist. It exists only on the sibling's development branch.
Why it matters
It is the first thing a new person types. It fails with an argument error, and the reasonable conclusion is that the tool is broken. This is the single most likely reason somebody tries it once and stops.
Action
The new guide already names it as trap one and points at sbe impact instead. Either hold the card back until the sibling releases, or reissue it naming impact.
When
Before the card reaches anybody. It predates tomorrow's release and is not blocked by it.

Alert 2. The documented first step turns the health check red

What it is
Surfacing your approved rules before a substantial task creates a provisional work record, but nothing rewrites the generated STATE.md view, so the health check reports that record as missing. It happened to this session tonight and failed the command-line suite with it.
Why it matters
A new team member follows the documented flow and lands on a red health check and a failing test suite, on their first task, with nothing telling them a checkpoint clears it.
Action
Small fix in one tool: have the record creation rewrite the view, the way the checkpoint already does. Decision D9 above is whether that lands tomorrow.
When
Before the team installs. It is a five-minute defect with an outsized first impression.

Alert 3. The gate poll read another session's verdict as its own, now fixed

What it is
This repository's own gate recipe polled for a sentinel file in a temporary directory that survives between sessions, and never cleared it first. Tonight the poll returned exit 0 after ten seconds while the real run was still going, and that run finished nine minutes later at exit 1 with two failed suites.
Why it matters
It fails toward green, which is the worst direction. A session could quote a passing gate it never ran.
Action
Fixed and committed at c4c8f70: the sentinel is cleared before launch and the wait is on the process, not the file. The reason is written into the recipe so it is not removed as clutter.
When
Done tonight.

Insight. A backend change that breaks a front end comes back as the lowest tier

What it is
A change that bumped an API path from v1 to v2 and added fields a front end reads was proposed as tier T0, the lowest, with every file marked unmeasured because no detector covers that file type. The verdict was NO-DATA, never a pass, and it said three times that it had not measured.
Why it matters
The tool is honest. The reader may not be careful. Somebody skimming sees T0 and ships a contract change to a consuming team.
Action
The guide teaches reading the unmeasured lines rather than the tier, and says plainly that the tier is a floor and never a ceiling. Your reviewers should be told the same sentence.
When
With the guide, now.
