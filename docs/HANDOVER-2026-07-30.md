## 4. Product defects found and fixed, with what caught them

Every one was found by running the real thing while the suite was green, or by a
reader told to REFUTE rather than review. Across three fleets: 25 refuted
verdicts against 14 upheld.

### Lessons, stated as rules

- **Test for absence.** "Something raised" passes when the wrong thing raises.
  Assert the refusal reason, not just the refusal.
- **Probe the binary.** Build fixtures from a REAL store (make one, then revert),
  then drive the actual command line. Every Critical above hid behind a green API test.
- **Prose in shipped help is a promise, therefore a test.** If the text says
  "refuses", a test proves the refusal.
- **A masking display path hides a leaking storage path.** Read the bytes on disk.
- **Scope every override.** An override answers one question at one moment.
- **Re-run the first command a stranger runs** after anything that moves its output.

## 5. Process failures of the orchestrator, with the mechanical fix

These cost more time than the product defects.

### 5.1 Committed on a red gate, TWICE, two different ways

First: chained `&&` after a pipe, so the exit code read belonged to `tail` and
`1 SUITE(S) FAILED` scrolled past. Second, worse because it was after writing the
lesson down: I committed the design spec (`91d48d8`) without running the gate at
all, assuming a documentation-only commit could not break tests. It did. The
doc-consistency suite required a HISTORICAL marker on every dated page under
`docs/`, and a live dated spec had none. Verified independently afterwards from a
clean `git archive` of that commit: `1 SUITE(S) FAILED`.

**Fixes, both mechanical.** Never read an exit code through a pipe: use
`${PIPESTATUS[0]}`, or read the printed verdict line. And run the gate after
EVERY commit, including documentation-only ones, because in this repository docs
are gated like code.

### 5.2 Ran the gate concurrently with other work

539 seconds instead of 60, because probes were importing the same modules while
suites renamed a module aside mid-run.

**Fix:** the gate gets the tree to itself. Background it and wait for the
notification rather than interleaving.

### 5.3 A worktree lane committed under the wrong author

One lane commit carried `BrotherMode Lane <lane@local>` instead of the founder's
identity, violating the rule that only Khalil Maaouni appears as creator here.
Caught by a scan before pushing; fixed by rewriting the unpushed range.

**Fix:** set `user.name` and `user.email` in every worktree at creation, and run
`git log --format='%an <%ae>' <base>..HEAD | sort -u` before every push.

### 5.4 A heading that overstated its own body

Twice a heading said COMPLETE while the body listed what was still open. An
automated drift check caught both.

**Fix:** the exception goes in the heading, not the body.

### 5.5 Long question lists as chat text

Corrected by the founder: decisions go through the client's native question
windows, two to four options, recommended first, at most four per round, ordered
by importance. Now law in `SKILL.md` and an approved store rule (`eeb754ad`).

## 6. Open defects found in passing and NOT fixed (each reproduced)

These were found by agents whose fence forbade the file that holds them. All are
real, all have a repro, none is fixed.

1. **`bm_store.py claim --help` creates a work record literally named `--help`.**
   `cmd_claim` prints usage only when argv is empty, so the flag becomes the name
   and the unknown-flag rejector never sees it. Register item 16, still live.
2. **`claim --objective "X" --files ...` with no positional name silently takes
   the string `--objective` as the record name** and creates the record.
3. **`bm_telemetry.py fence-lint` reports "no live fences found" against a
   STATE.md holding two active records.** It only matches hand-written V1 fence
   lines containing the word `agent` (around line 1178), so it is blind to the
   store-rendered format. Either the tool or the sentence in
   `docs/HOW-IT-WORKS.md` is wrong; a session owning both must decide.
4. **`--handover "<heading>"` is the whole person-to-person handover mechanism
   and appears in no usage line.** Undiscoverable from the CLI.
5. **Every STATE.md render writes another `STATE.md.bak-<timestamp>`.** Seven
   accumulated in fifteen minutes, and the autosave warning then lists them all.
   Cap them or ignore them.
6. **`bm_learn.py capture` with no arguments captures an EMPTY candidate**
   instead of printing usage, while the same CLI correctly refuses unknown flags.
7. **Unauthenticated alert resolution.** Anything able to run `bm_learn.py` can
   resolve a critical alert, after which an approval proceeds unblocked. It cannot
   be done quietly (the resolution text, author and timestamp render in the pack),
   but only the receipt-gated override has a human answer behind it. Closing this
   needs an identity notion the project does not have. **Founder decision owed.**
8. **The doc-status guard keyword-matches too loosely.** `test_bm_docs.py`
   around line 350 treats any occurrence of the historical marker word in a
   page's header as the page declaring itself historical, then demands a
   superseded-by pointer. Reproduced while writing THIS file: a sentence merely
   describing the convention failed the suite. Harmless but it will bite anyone
   documenting the rule. Match the marker at line start, not anywhere.
9. **A real intermittent failure in the store suite, sighted three times, with a
   measurable correlate.** Signature: inside a full `test_all.py` run the store
   suite reports `FAILED (failures=1)` while no FAIL line survives into the
   summary; run alone it passes. Sighted by the Phase B agent, then twice by the
   orchestrator, the last time in a CLEAN extraction of the handover pack, which
   rules out a dirty working tree. **The correlate: it fails when that suite runs
   slowly.** Failing runs took 71 seconds; passing runs of the same suite take 12
   to 13. That points at a timing or contention-sensitive case, most likely in the
   randomized-sequence class, rather than at a logic defect. Do not retry it away.
   Reproduce it under deliberate load (run the gate with the machine busy), then
   seed the sequence and make the interleave deterministic.
10. **A second known flake:**
   `test_calibrated_without_the_lock_the_same_pair_duplicates_the_handover`, a
   deliberate two-thread race with the lock stubbed out, so the reproduction
   sometimes does not reproduce. Needs a deterministic interleave too.

## 7. Honest reductions against the spec, disclosed

- **Documentation prose is ASSEMBLED, not written by a model.** The spec calls
  prose "paid"; there is no model at generation time, so every narrative block is
  composed from recorded fields and invents nothing. The fact-hash cache is real
  and calibrated, and it is the socket a model-written block would plug into. This
  is a genuine reduction and it is hidden nowhere in the code.
- **The exporter ships one writer, not three.** Spreadsheet output works
  (`openpyxl` or `xlsxwriter`); PDF and Word are REFUSED with a stated reason
  even on a machine that has a PDF library, because an untested backend is worse
  than a named gap. The no-subprocess invariant also rules out pandoc and
  LibreOffice. **Founder call if PDF and Word matter.**
- **The book's PDF was produced by hand** with headless Microsoft Edge and that
  is documented verbatim beside it, because the project's own tooling cannot make
  one.
- **`Documentation/` is gitignored** in this repository, on the same grounds as
  `STATE.md`: its pages render live store rows, real claimed paths and owner
  names. Regenerate with `python3 tools/bm_docs.py generate`.
- **Alert refusal covers the change set the STORE records** (the work record's
  claimed paths plus an artifact scope key), not a pack's citations. A cited file
  nobody claimed cannot be guarded; the pack prints the claim command that closes
  the gap.
- Two small spec ambiguities were resolved by the implementer and want a founder
  ruling: where `BA-SUMMARY.md` sits in the tier table, and where the whitepaper
  lives.

## 8. Environment and tooling traps

| Trap | Symptom | What to do |
|---|---|---|
| Harness safety-classifier outage | `Bash`, `Write`, `Edit`, `Monitor`, browser tools all refuse as "temporarily unavailable"; computer use survives | Do not loop on retries. Verify from read-only channels: `.git/FETCH_HEAD`, `.git/logs/refs/remotes/origin/*`, `.git/refs/*`. Report the blocker, resume when it clears |
| GitHub Desktop will not push a tag made at the command line | The tag exists locally and never reaches the remote | Create it THROUGH Desktop (History, right-click the commit, Create Tag), then push. Confirmed empirically |
| Chrome extension not connected | No release page, no browser automation | Founder opens the Claude side panel in Chrome, or takes the click path |
| `gh` logged out | No pull request from the CLI, ever | Founder-only `gh auth login`; credentials are never typed by Claude |
| Another Claude session holds the computer | Computer use refuses outright | One GUI driver at a time; wait or ask the founder to stop the other session |
| An app steals frontmost | Clicks land nowhere or are refused | `osascript -e 'tell application "X" to activate'` then System Events `set frontmost` |
| Desktop shell frontmost | Computer use refuses the click | `open_application` the target, then retry |
| `bm_learn.py` has no `--help` | Guessing flags wastes turns | Pass a deliberately bad flag: it prints the recognized list and exits non-zero |
| Browser preview tool on a `file://` URL | Timed out after 300 seconds, unusable | Headless Edge screenshots read back as images worked instead |
| `bm_learn.py inbox` reads the SHARED vault | It printed five real founder corrections from an unrelated project into a probe transcript | Set `BROTHERMODE_VAULT` to a throwaway path for any demo, screenshot or recording |

## 9. Store and migration safety

The live store in this repository is at **schema 7** and the collaboration layer
takes it to **8** on its next command (one additive column,
`notes.anchor_line_hash`, guarded by `PRAGMA table_info`, no backfill because a
fingerprint taken today would falsely claim today's line was the anchored one).

A schema-8 store cannot be opened by an older `bm_store.py`. That is the normal
forward direction here, but anyone holding an old clone should know.

A durable backup was taken before any migration:
`~/Documents/BrotherMode-store-backups/store-pre-schema8-20260730.sqlite3`
(the fleet's own backup went to `/tmp`, which is wiped, so it was copied out).

## 12. The habit worth carrying forward

the build.
