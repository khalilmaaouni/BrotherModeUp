BrotherME for Claude Code

A careful project partner, explained simply

You describe what you want in plain words. BrotherME plans it with you, does the work with the right helpers, and refuses to call anything finished until a real check has passed.

What it actually is

Claude Code out of the box is a very capable worker that waits for instructions. BrotherME turns it into a careful colleague. Before building anything, it agrees the goal and direction with you. While working, it tells you what is happening in plain language, keeps a written record of decisions and progress that survives crashes and restarts, and brings you bad news first instead of burying it. And when it says something is done, that claim always comes with proof: a check that ran after the last change and passed.

You never need to learn the machinery. If you can describe what you want and answer a few plain questions, you can use it.

Install it in two lines

Open Claude Code and type these two commands, one at a time:

/plugin marketplace add khalilmaaouni/BrotherModeUp
/plugin install brotherme

If Claude Code asks which source to install from, pick the one you just added, and restart if it tells you to. That is the whole install. To check it worked, type /brotherme-help. To remove it later, type /plugin uninstall brotherme; your projects and records stay untouched. To upgrade, follow the current QUICKSTART page in the repository, which always carries the exact commands for the newest release.

The six commands

/brotherme-startBegin a project. It asks what you want to accomplish and turns your answers into a one-page project brief you approve before anything is built.
/brotherme-statusWhere things stand: goal, progress, time remaining, any decision waiting on you, and the evidence behind each claim.
/brotherme-nextThe single best next step, with a reason and an honest time range.
/brotherme-reviewChecks finished work against a written definition of done, point by point, and never softens a failing point.
/brotherme-deliverWraps up. Delivery requires proof; without a passing check it tells you plainly what remains instead.
/brotherme-helpExplains what you have and what to do next, in plain words.

How the work gets done: the guided loop

Under the surface, every piece of delegated work runs through the same four-stage loop. The strongest model available does the thinking and the judging; cheaper, faster models do the labor. You get top-grade judgment without paying top-grade prices for routine work.

1. Guide. The coordinator, on the strongest model, writes precise instructions: what to do, which files may change, and the exact check that will prove success.
2. Execute. A cheaper helper does the work. Mechanical jobs go to the fastest tier, scoped building work to the middle tier.
3. Verify. A separate reviewer, never the one who did the work, tries to prove the result wrong rather than to confirm it.
4. Land. The coordinator re-runs the proving check itself before accepting anything. A pasted result is a claim; the re-run is the evidence.

If a helper fails its check twice, the work moves up one grade with the failure attached, instead of looping forever. In everyday language, all of this is just "picking the right helper for the job."

What it protects you from

Four everyday failures, each with a built-in guard. Losing work: it saves progress to disk before the AI's memory fills up, so a crash or restart does not lose the thread. Two workers overwriting each other: one writer per file at a time, and a mechanical gate enforces it rather than a promise. Confident nonsense: nothing gets called done without a check that ran and passed after the last change. Quiet scope drift: decisions go through you, one at a time, with a recommended option first.

Honest limits, before you rely on it

  • This is release candidate 2.0.0-rc.10, not a finished 2.0.0. The remaining step is real: nobody has yet run it on live day-to-day work for a full week.
  • The two-line install above has been through its full cycle exactly once, on the author's machine. You may be the first person to run it from GitHub. If it misbehaves, the repository's issue page wants to hear about it.
  • It is verified on Claude Code only. Other AI coding tools get advisory files, not enforced guarantees.
  • Use one install path, not both. The plugin and the older clone-based install wire the same automation; a machine carrying both runs everything twice.
