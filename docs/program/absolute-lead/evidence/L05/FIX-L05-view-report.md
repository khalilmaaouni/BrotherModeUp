## Deviations from the design, each with its reason

1. **COMMANDS has six entries, not five.** Section 12.2 says five and
   lists five, but section 12.3 wires `bm-view alert --tick` on Stop
   and section 13.2 tests it; a subcommand not in COMMANDS cannot
   dispatch, and the consent inventory (tools/test_bm_consent.py:620
   area) requires a cmd_ function per wired subcommand. `alert` is the
   sixth entry.

2. **render_page takes seven inputs, not five.** Section 12.2 writes
   `render_page(status, alerts, insights, briefings, decisions)`. The
   landed builders take `visual_facts(...)` (Writer D deviation 1), and
   the setup counter is computed from rows, so `facts` and `milestones`
   are two further pure inputs. The five named ones kept their names
   and their order; nothing reads the store inside render_page, and
   build_page is the one gatherer.

3. **D4 is drawn once, beside the highest stakes decision in
   #decisions; #your-move links to it instead of drawing it again.**
   Sections 4.2 and 8.1 both ask for the fork, but the four-drawings
   cap (section 4.2) is stated as reached exactly by sections 4, 6, 8
   and 9. Drawing the fork twice, or once per open decision, breaks the
   cap the moment it matters. The panel carries the option lines, the
   copy as prompt control and an in-page anchor to the drawn fork.

4. **The plain language scan excludes "branch", with the reason in the
   test.** The terminology row is "worktree, branch", the git workspace
   concept. The page's one use is tools/bm_visual.py's landed fork
   caption ("The last branch is always yours: ..."), the everyday arm
   of a drawn fork, in Writer D's file which I may not edit. Flagged
   here for the orchestrator to adjudicate: either the caption is
   reworded in bm_visual.py, or the terminology row gains a note that
   the drawn fork's arm is permitted.

5. **The SQL literal guard matches SQL shapes, not bare keywords.** The
   controller-suite shape (bare SELECT/INSERT/UPDATE/DELETE/PRAGMA
   words) false-positives on Writer D's landed founder prose ("Update
   BrotherMode, then try again.", a REFUSAL_HELP next action). The
   landed guard requires the clause that makes a keyword executable
   (SELECT..FROM, INSERT INTO, UPDATE..SET, DELETE FROM, PRAGMA x().
   A fix at the class (detect SQL, not English), not a narrowing: both
   new modules stay fully covered, sqlite3 imports stay banned.

6. **A row that cannot fill all six insight slots renders as its
   labelled claim line, never as a shorter box.** bv.insight_box_slots
   raises on any empty slot by design, and a founder's ledger may hold
   minimal rows recorded before L05, so the page must still render.
   The rendering used is bl.render_claim_text, which keeps the
   renderer-applied evidence label, and no five slot box can exist.
   VERIFIED, not assumed:
   test_a_minimal_row_renders_as_a_labelled_line_never_a_short_box
   drives a minimal pre-L05 shaped row through the page and asserts
   both halves (the labelled line appears; every rendered box carries
   exactly the six INSIGHT_SLOTS labels).

7. **The Stop-hook alert dedupe is alerts_now's own.** Section 6.3 rule
   4's "already interrupted since the previous briefing" suppression
   would need stored read-state, which L-S6 forbids and the store does
   not hold. alerts_now already dedupes and caps per call (Writer D's
   landed shape); alert --tick emits at most the single top NEEDS YOU
   object per tick and nothing else.

8. **Pre-consent, the hook-wired invocations are silenced by exact
   shape.** main() returns 0 silently for `alert` and for `render` only
   when `--if-stale` is present; a human typing `bm-view render` before
   setup still gets the setup sentence and exit 1. This is bm_lead.py's
   watchdog rule extended to the two wired spellings, asserted in
   TestConsentIsTheOnlyDoorForTheView.
