SL-quick part 1, in full. RF-5: tools/test_all.py now writes .brothermode/gate-receipt.json (commit id, whether the tree was dirty, test and suite counts, skipped, wall seconds, exit code, timestamp) into the ignored directory, never the tracked tree, because the gate itself refuses a run that dirties tracked files. It fails open on purpose: git missing, a non-checkout, or a full disk warns on stderr and never changes the verdict, proven by a test that runs it outside a repository. RED first, quoted by the builder: "AttributeError: module 'bm_test_all_under_test' has no attribute 'write_gate_receipt'". RF-1: scripts/bm_commit_msg_hook.py refuses an em dash, an en dash, or a Co-Authored-By line, naming the offending line number, exit 1; a clean message exits 0. Both verified live by the orchestrator, not only by the builder, and the hook was installed at .git/hooks/commit-msg and screened its own landing commit. The builder deviated once, deliberately and correctly: it registered the new script in the write-sites manifest, outside its allowed file list, because the repo's own pre-write gate demands an entry for any file that writes to an output channel; it read the loader first and reproduced the red before editing. Suites after the last edit: the two new test classes "Ran 10 tests in 0.318s OK", tools/test_bm.py "Ran 290 tests OK (skipped=1)", tools/test_bm_docs.py "OK (skipped=1)".
