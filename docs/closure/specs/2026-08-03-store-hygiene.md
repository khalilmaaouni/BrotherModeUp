## Summary

C-08 and C-09 both live in tools/bm_store.py, both have exact narrow fixes with a matching precedent already in the codebase.

C-08: render_state_md() (starts line 11056) builds STATE.md's header with `"_Generated by bm_store.py, %s. ..." % now_iso()` at lines 11088-11089, stamping wall-clock time into every render. bm_project.py's render_canvas() (CANVAS.md, line 468) already solved this by carrying NO render-time timestamp; its docstring (474-477) says a "generated at" line would make two regenerations of identical rows differ by nothing but the clock. No single "last changed" value in the state covers every field render_state_md prints (records.updated_at, provisional_records.created_at, digests' newest created_at, handovers.created_at all move independently), so deriving one would be dishonest or need a multi-table MAX() scan for a cosmetic banner line. Fix: EXCLUDE, mirroring CANVAS.md's convention.

Found while reading: TestStateView.test_write_state_view_regenerates_byte_stable_across_three_renders (test_bm_store.py line 3843) already FREEZES now_iso to work around this bug -- its own docstring says so. That is the suite tolerating the defect, not proving its absence.

C-09: Store._quarantine_and_raise (starts line 4913) creates the quarantine dir with `os.makedirs(qdir, exist_ok=False)` (line 4962), never chmods qdir, while every file inside gets 0o600 via _chmod_best_effort (4989, 5008, 5031). Store.__init__ already mirrors this for .brothermode/: makedirs (4131) then `_chmod_best_effort(expected_store_dir, 0o700)` (4167), same helper (defined line 3231), same mode. Fix: one added call right after qdir is confirmed to exist, before anything is copied/moved into it.

All names and line numbers confirmed by reading the file directly.

## Risks

C-08: removing the timestamp changes STATE.md's on-disk text for every project (one line loses its date) -- a visible, intentional change a founder reading STATE.md by eye will notice. No parser breaks: grep for 'Generated by bm_store.py' outside bm_store.py/test_bm_store.py found nothing else in tools/. The existing frozen-clock test (line 3843) still passes after the fix -- its mock.patch.object(bs, "now_iso", ...) becomes a no-op patch of a function render_state_md no longer calls there -- but its docstring's stated rationale ("now_iso is frozen so the timestamp ... cannot be the thing that changes") goes stale. Not required to close C-08; a docstring correction there is optional and not included in changes since it is prose-only.

C-09: none identified. _chmod_best_effort is already best-effort/non-raising (docstring: failure or platform no-op is "expected and never escalated"), so one more call cannot introduce a new failure path. New test is POSIX-only (skipped on win32), matching the analogous .brothermode/ permission test.

### tools/bm_store.py

Anchor: render_state_md, header line (function starts line 11056; block at lines 11087-11090)

Why: Sole timestamp injection point in render_state_md's output (confirmed by reading the whole function, 11056-11184). The only other datetime call in write_state_view (line 11328) names the STATE.md.bak-<stamp> BACKUP file, a side file, out of scope. Removing %s/now_iso() makes two renders of unchanged state byte-identical, matching CANVAS.md's precedent instead of inventing a new one.

```
        lines = [_STATE_BEGIN,
                 "_Generated by bm_store.py, %s. Edit outside the markers; "
                 "anything inside them is overwritten on the next render._" % now_iso(),
                 ""]
```

Replacement:

```
        lines = [_STATE_BEGIN,
                 # C-08 fix: deliberately carries no timestamp of its own
                 # render time, mirroring bm_project.py's render_canvas
                 # docstring verbatim (CANVAS.md already settled this exact
                 # question). Byte-stability across renders of unchanged
                 # rows is the whole point of write_state_view's own GATE
                 # A/B backup-and-splice machinery; a "generated at" line
                 # would make two back-to-back regenerations of identical
                 # state differ by nothing but the clock. No single
                 # "last changed" value in the state covers every field
                 # rendered below (records.updated_at, provisional_records.

                 "anything inside them is overwritten on the next render._",
                 ""]
```
